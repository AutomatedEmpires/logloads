**Five P1 findings you must resolve before merging** (numbers are the reviewers' priority, not mine):

1. **A host can never attach a card, so a host can never publish.** `hostBillingProfiles` starts empty for

3. **A credential with a blank stated expiry never expires.** If the model reads a real future expiry but

   "unbilled".
5. **The backup restore is not CAS-safe.** It PATCHes unconditionally, so it can erase a concurrent write
   and reuse its version. I justified this in a comment as deliberate operator override; the reviewer is
   right that it should be version-gated with a zero-row failure and a post-write re-read.

## 3. Architecture you must understand before touching anything

**The entire database is ONE JSONB row**: `public.operating_state` id=`'primary'`, read and written whole
under a `version` compare-and-swap, using the service-role key.

There are 38 relational tables and 39 RLS policies. **They are empty and unread.** `load_postings`,
`profiles` and `companies` all have 0 rows in production. Verified by direct query.

Consequences you cannot design around:

- **No unique index, no foreign key, no CHECK constraint.** Deterministic ids plus explicit assertions are
  the only integrity. Every guard needs a test that fails when the guard is removed.
- **Every check must run inside the same mutation as its write.** A check before `mutateState` is defeated
  by a CAS retry.
- **Application TypeScript is the only security boundary.** RLS contributes nothing at runtime.
- **Rows are now zod-parsed on read** (`packages/db/src/snapshot.ts`). `ROW_VALIDATORS` is an exhaustive
  `Record<LogLoadsTableName, RowValidator>` — **a new collection will not compile until you declare its
  validator**, and it needs an additive `?? []` backfill or the first production read refuses the whole
  document and every request fails.
- A malformed row is **withheld, not dropped** — withheld rows travel on the snapshot and are re-appended
  on write, because in a write-whole store dropping a row means the next CAS erases it from Postgres.

## 6. Traps — read this section twice

- **Check that new code is CALLED, not just that it exists.** The fee accrual service was built, tested,
  exported and bound on the services facade with **zero call sites**. A fee engine nothing calls earns
  nothing. `fee-accrual-wiring.test.ts` exists solely because of this. Grep for call sites before believing
  a feature works.
- **Seed changes never reach production.** The canonical row is only created when none exists, so
  production still holds an early seed (6 loads, 11 profiles, cas version 3). `/api/health`'s
  `engine.profiles: 11` is **seed personas**, not business data. Do not use it as a metric.
- **On deploy, production's publish and request paths will refuse.** The new collections backfill to `[]`,
  so no seeded host has a billing profile and no driver has credentials. That is the gates working
  correctly, not an outage — nothing errors, it refuses. Refresh the canonical state or create records when
  you want the demo working again.
- **The migration ledger has diverged from this repo.** All applied versions carry Studio/MCP-generated
  timestamps matching no filename; two migrations exist only in production; two repo files were never
  recorded. **Apply migrations through CI, never through MCP or Studio** — an out-of-band apply is what
  caused this, and it took a sibling product down.
- **CI has no Supabase credentials.** That is why the required `migrations` check never touches a real
  database and the drift went unnoticed. Backups cannot be scheduled until secrets exist.
- **The e2e suite is NOT a required status check**, and `enforce_admins` is false. A PR with every browser
  journey red is mergeable, and merging `main` auto-deploys production. Fix this early.
- **Two existing tests asserted the defects they covered** (`rate-limit-client-key.test.ts` pinned the
  shared-bucket constants; `economics.test.ts` pinned the rate-card derivation). Expect more of this. When a
  test blocks a correct fix, rewrite it deliberately and say so — do not weaken it to go green.
- **`information_schema.role_table_grants` is not the authority on privileges.** It reported `anon:TRUNCATE`
  after the revoke had worked, because those rows were PostGIS *views*. Use `has_table_privilege`.
- **Objects are updated immutably.** A test holding a reference from before a mutation is asserting against
  a stale copy. Re-read from state.
- **Hand-computed constants belong in tests, and they will catch you.** A degree of latitude is 69.09409
  miles, not 69.0932 — the absolute assertion caught the wrong constant immediately.
- **Parallel agents must own disjoint files.** Two agents editing one file corrupts work. Partition by file
  and state ownership explicitly.
- Local e2e flakes under load; only clean-runner CI is trustworthy. `pnpm build` races a running dev server.
  Playwright reuses an existing server on :3002 — kill the bench first or you test the dev server.
